# AgentScope 2.0 Web 会话与后台事件迁移设计

日期：2026-07-14
状态：已确认，待实施计划

## 1. 背景

当前 DataPilot Web 前端使用自定义 WebSocket、事件模型和 reducer，AgentScope 2.0 主要只用于后端智能体运行。真实数据测试暴露了两个 P0 问题：

1. Web 事件订阅与单轮请求绑定，遇到 ToolOffload 后台完成触发的 wakeup run 时，原订阅已经在首个 `REPLY_END` 后退出，导致后台真实结果和第二轮智能体回复未显示。
2. ToolOffload 的占位 `ToolResponse(state=SUCCESS)` 被前端当成真实工具成功，工具卡提前变绿；后台真实业务结果可能随后返回 `ok=false`。

同时，`goal.md` 要求 DataPilot 对用户保持单一智能体形象、历史会话均可恢复并继续交互、支持删除与中断，并在执行失败时理解真实错误、读取状态并安全重新规划。

本设计选择保留 DataPilot 的界面和产品身份，将底层会话、消息和事件语义迁移到 AgentScope 2.0，而不是直接采用官方 AgentScope Web UI。

## 2. 已确认的产品语义

### 2.1 会话

- 任意已保存会话都可以重新选中并继续发送消息。
- 重新进入会话时恢复此前的 AgentScope 上下文、Navigation 任务、Plan 和执行状态。
- “历史会话”只表示列表中的旧记录，不表示只读状态；移除当前 `active/historical` 对可写性的区分。
- 浏览器只为当前选中的会话维护实时连接，不为每个历史会话分别维持连接。

### 2.2 工具卡

工具卡状态为：

```text
开始调用 -> 正在调用 -> 成功
                    -> 失败
                    -> 已停止
```

- “已转后台”不是工具状态。
- ToolOffload 占位响应不能结束工具卡。
- “已停止”只能由明确的用户停止操作产生。
- 其他异常、取消、业务 `ok=false` 均为“失败”。
- 每个 `tool_call_id` 只能写入一次终态。

### 2.3 删除

- 删除会话可以删除会话消息、AgentScope 会话状态、公开事件和相应控制面执行记录。
- 删除会话绝不删除已经产生的数据集、同步数据、处理结果或其他业务产物。
- 删除逻辑只允许操作明确列入白名单的会话/控制面存储，不接受任意业务文件路径。

### 2.4 开发期数据迁移

- 不兼容迁移当前测试用 Web 会话和 AgentScope session 映射。
- 实施时允许清空开发期测试会话、AgentScope 状态和关联控制面记录，并按新 schema 初始化。
- 清理范围不得包含数据集根目录、拆解/同步输出目录或其他处理产物目录。

## 3. 目标与非目标

### 3.1 本次目标

- Python AgentScope 从 `2.0.1` 升级到 `2.0.4`。
- 前端引入 AgentScope TypeScript SDK，使用其消息、事件和增量合并语义。
- 建立不依赖浏览器在线状态的持久化事件投影。
- 可靠显示 ToolOffload 后台完成事件和 wakeup run。
- 支持会话恢复、删除、中断和重新发送消息。
- 保留失败步骤的只读执行状态和完整失败结果。
- 阻止一次性副作用工具在失败或中断后被自动重跑。
- 对用户隐藏 MainRouterAgent、NavigationDataAgent 和内部 AgentScope session。

### 3.2 非目标

- 不把拆解/同步改造成增量处理、断点续跑或产物修补工具。
- 不实现 Navigation Skill。
- 不建设完整智能体评测框架。
- 不在本任务中清理 CLI/TUI 和旧 Plan/Executor 遗留代码。
- 不重写整个 Navigation 动态规划体系。
- 不直接替换为官方 AgentScope Web UI。

## 4. 方案选择

采用“DataPilot AgentScope 原生协议网关”方案：

```text
DataPilot React 前端
  <-> DataPilot 公开会话 API / SSE
  <-> 持久化公开事件时间线
  <- AgentScope 事件投影中间件
  <- AgentScope MainRouterAgent / NavigationDataAgent
```

该方案保留一个稳定的公开 DataPilot session，允许其内部先后映射到 MainRouterAgent 和 NavigationDataAgent 的 AgentScope session，同时不向浏览器暴露这些内部结构。

未选择的方案：

- 直接采用官方 Web UI：会暴露内部 agent/session，无法自然保持 DataPilot 单一智能体身份。
- 仅延长现有 WebSocket 订阅：仍维护两套事件协议，且不能从根本上消除 run replay 裁剪竞态。

## 5. 架构与职责

### 5.1 AgentScope Runtime

- 负责智能体运行、消息记忆、HITL、ToolOffload、后台任务与中断。
- 所有 MainRouterAgent 和 NavigationDataAgent 运行均安装 DataPilot 事件投影中间件。
- 投影发生在事件生产路径上，不能依赖单轮 Web 请求创建的临时订阅者。

### 5.2 DataPilot 会话网关

- 对浏览器暴露稳定的公开 session ID。
- 维护公开 session 与内部 AgentScope session 的映射以及当前路由目标。
- 接受发送消息、中断、删除和会话元数据请求。
- 对 AgentScope 事件做身份脱敏和公开协议投影。
- 不承担智能体业务决策，也不复制 AgentScope 的运行状态机。

### 5.3 持久化公开事件时间线

- 每个公开 session 的事件具有单调递增 `sequence`。
- 每个事件具有稳定去重键，重复投影不得产生重复 UI 内容。
- 事件先持久化，再向在线 SSE 订阅者广播。
- AgentScope run 完成和内部 replay buffer 裁剪不影响公开时间线。
- 服务重启后可以从最后持久化序号继续读取。

### 5.4 DataPilot React 前端

- 使用 AgentScope TypeScript SDK 的消息/事件类型和增量 reducer。
- 保留现有 DataPilot 视觉、会话列表和工具卡设计。
- 仅消费公开、脱敏后的 DataPilot session/event；不理解内部 agent 路由。
- 页面运行态由 AgentScope 的 run/reply 事件驱动，不由发送请求是否返回驱动。

## 6. 会话与事件流程

### 6.1 选中会话

1. 关闭此前选中会话的 SSE。
2. 加载新会话的持久化消息、工具记录、最新 `sequence` 和当前任务状态。
3. 恢复同一公开 session 对应的 AgentScope 上下文。
4. 建立当前会话 SSE，并从客户端最后确认的 `sequence` 补齐事件。
5. 会话无论创建时间多早，均允许继续发送消息。

### 6.2 发送消息

1. 网关持久化用户消息并接受运行请求。
2. 请求在确认接受后返回，不等待整轮完成。
3. AgentScope 在该公开 session 的当前内部映射上运行。
4. 事件投影器持久化所有前台、后台完成和 wakeup run 事件。
5. 在线时通过 SSE 实时推送；离线时下次进入会话补齐。

### 6.3 SSE 连接

- 一个页面只维护当前选中会话的连接。
- 接口支持 `after_sequence`，断线重连不会重放已经确认的 UI 事件。
- 心跳只维持连接，不改变会话或运行状态。
- 慢客户端不能阻塞 AgentScope 运行；持久化时间线是事实来源，内存广播仅用于降低延迟。
- 如果未来需要让侧边栏实时显示其他会话完成状态，应增加单个用户级通知通道，而不是每会话一个连接；不属于本次必需范围。

## 7. 工具事件与真实终态

### 7.1 权威来源

- 工具开始事件可从 AgentScope tool call 事件投影。
- 工具终态必须来自真实底层 `ToolResponse` 或 DataPilot 取消终结器。
- ToolOffload 创建的合成占位成功只表示工具已转入后台，对公开工具卡没有终态意义。
- 业务工具包含 `ok` 字段时，`ok=false` 优先于 AgentScope 外层 `SUCCESS` 状态，最终为失败。

### 7.2 状态判定

- 成功：真实底层响应成功，且结构化业务结果不存在 `ok=false`。
- 失败：真实底层异常、业务 `ok=false`、非用户触发的取消或无法安全完成。
- 已停止：用户明确点击停止，并且 DataPilot 对该调用完成了停止终结。

### 7.3 幂等终结

- 为公开工具调用持久化 `tool_call_id`、开始时间、终态和终结来源。
- 终态写入使用条件更新；已有终态时忽略后续占位或重复事件。
- 后台真实结果到达时更新原工具卡，不创建第二张工具卡。
- 如果服务在工具运行期间重启，恢复逻辑根据 AgentScope 后台任务状态或持久化结果终结卡片，不能永久停留在“正在调用”。

## 8. 中断语义

用户点击停止时：

1. 网关向 AgentScope 2.0.4 发出当前 chat run 中断。
2. 取消该公开 session 当前运行关联的后台工具任务。
3. 已进入本地处理子进程的工具通过现有 cancellation context 终止进程组。
4. 未结束的公开工具卡写入“已停止”。
5. 保留停止前的消息、Plan、证据和只读执行状态。
6. AgentScope 发出终止 reply/run 事件后，原会话重新允许发送消息。

中断不等同于删除：中断保留会话和业务产物；删除清除会话控制面状态，但同样保留业务产物。

## 9. 会话删除与数据安全

删除顺序：

1. 标记公开 session 为 deleting，拒绝新消息。
2. 中断仍在运行的 chat 和后台工具。
3. 删除该公开 session 映射的内部 AgentScope session/state。
4. 删除公开消息、事件、工具卡和白名单内的 Navigation 控制面记录。
5. 删除公开 session 记录。

安全约束：

- 删除 API 不接受文件系统目标参数。
- repository 只操作已知数据库表和专用会话状态目录。
- `raw_data_root`、`clip_data_root`、`finish_data_root`、数据集根目录及其子目录不允许出现在会话删除实现中。
- 删除测试会话数据的开发期初始化脚本遵循相同约束。

## 10. 失败诊断与安全恢复

### 10.1 失败活动状态

步骤失败后进入明确的 `failed_recovery`，不再回退为普通 `planning`。此状态暴露：

- 当前任务、Plan 和失败步骤的只读状态。
- 完整执行结果读取。
- 证据读取、产物检查和诊断工具。
- 仅在安全条件满足时可用的完整 Plan 提交工具。

此状态不暴露原失败副作用动作或通用执行动作。

### 10.2 失败结果读取

新增按当前任务、`plan_id` 和 `step_id` 定位的只读结果工具，后端解析真实 `result_ref`，不要求模型携带不透明引用。返回内容包括：

- 错误类型、错误消息。
- 命令退出码及有界 stdout/stderr。
- 结构化业务结果。
- 已生成路径和中间产物。
- 大结果的字段选择、分页或有界摘要。

### 10.3 副作用完成度

执行结果显式记录副作用状态：

- `not_started`：处理命令尚未启动，可在修正输入/Plan 后重新执行。
- `completed`：真实工具成功完成。
- `partial_or_unknown`：命令已经启动但失败、停止或完成情况无法证明。

`partial_or_unknown` 不能根据目录存在推断为成功，也不能自动生成再次调用相同一次性工具的 Plan。

### 10.4 拆解/同步工具的边界

当前 `extract_and_sync_navigation_data` 对每个所选 segment 执行完整拆包和完整同步：

- 没有只补缺失产物的参数。
- 没有断点或子阶段恢复接口。
- 直接写入原 `tmp_dir` 和 `sync_data`。
- 不清理或隔离旧产物，因此完整重跑不具备可靠幂等性。

本次只让 Agent 能读取真实错误、识别 `partial_or_unknown` 并阻止危险重跑。若未来需要可靠恢复，应另行设计 attempt 隔离目录、子阶段拆分、产物清单和验证后原子发布。

## 11. 公开协议与数据模型

建议的最小公开资源：

- `PublicSession`：公开 ID、标题、创建/更新时间、当前运行摘要。
- `PublicEvent`：session ID、sequence、去重键、AgentScope 兼容事件负载、时间。
- `PublicToolRun`：tool call ID、公开工具名、状态、开始/结束时间、失败或停止原因。
- `InternalSessionBinding`：公开 session 到内部 AgentScope session/role 的私有映射。

不在公开负载中出现：

- MainRouterAgent、NavigationDataAgent 名称。
- 内部 AgentScope session ID。
- 内部路由 handoff 内容。
- 服务器文件系统敏感路径；允许展示给用户的业务产物路径需经过现有路径策略。

建议的最小 API：

- 列出、创建、读取和删除公开会话。
- 向公开会话发送消息。
- 中断公开会话当前运行。
- 读取公开会话快照。
- 订阅公开会话 SSE，支持 `after_sequence`。

## 12. 与 `goal.md` 的对应关系

本次直接覆盖：

- DataPilot 单一智能体用户体验，隐藏内部多智能体协作。
- 任意历史会话可恢复、可继续发送消息。
- 删除会话。
- 更及时、确定的用户中断体验。
- 失败后理解真实错误、读取执行状态和安全重新规划的基础。
- 产物检查优先，且不根据部分产物伪造成功。
- 精简会话和工具状态，避免冗余或误导性状态。

后续独立处理：

- Navigation Skill。
- 智能体评测体系。
- CLI/TUI 与旧架构清理。
- 拆解/同步的可恢复处理流水线。
- 更广泛的动态 Plan 能力演进。

## 13. 验收测试

### 13.1 后台 wakeup

- ToolOffload 超时转后台后，首轮 `REPLY_END` 不会停止事件持久化。
- 无浏览器连接时，真实后台结果和 wakeup run 回复仍进入公开时间线。
- 重新打开会话能够按序看到完整结果。

### 13.2 工具卡

- 占位成功后仍为“正在调用”。
- 真实 `ok=true` 终结为成功。
- 真实 `ok=false` 终结为失败。
- 用户停止终结为已停止。
- 重复和乱序终态事件不改变首次权威终态。

### 13.3 会话

- 任意保存会话都可继续发送消息并沿用上下文。
- 服务重启后会话、任务、Plan 和事件可以恢复。
- 切换会话不会串流事件。
- 只为当前选中会话维持实时连接。

### 13.4 删除

- 删除后公开会话及其 AgentScope 状态不可恢复。
- 删除期间正在运行的任务会被终止。
- 数据集、`sync_data`、finish 输出及其他处理产物逐项断言保持不变。

### 13.5 中断

- 推理、HITL 等待和可取消后台工具均能结束。
- 本地子进程组被终止，不永久转圈。
- 工具卡显示“已停止”。
- 同一会话完成收尾后可继续发送消息。

### 13.6 失败恢复

- 失败步骤保持只读执行状态可见。
- 可按 plan/step 读取真实错误、退出码和 stderr。
- `partial_or_unknown` 不会暴露同一副作用工具的自动执行入口。
- 重复调用旧失败 step 不会重新执行底层动作。

### 13.7 产品身份与隔离

- 浏览器公开响应和事件不包含内部 agent/session 标识。
- 两个公开会话并发运行时消息、工具卡和 Navigation 状态相互隔离。

## 14. 实施顺序与风险控制

建议顺序：

1. 升级 AgentScope 并建立版本兼容测试。
2. 建立持久化公开事件投影和 SSE，不先改 UI 外观。
3. 完成真实工具终态与 ToolOffload 占位过滤。
4. 前端切换 AgentScope SDK 事件 reducer。
5. 完成会话恢复、删除和中断。
6. 完成 `failed_recovery`、结果读取和副作用状态约束。
7. 删除旧自定义 WebSocket/turn-scoped bridge 和开发期测试会话数据。
8. 运行单元、集成、服务重启和真实后台处理验收。

主要风险：

- AgentScope 2.0.4 与 2.0.1 的内部事件/中断接口差异：通过适配层和契约测试隔离，不修改 AgentScope 源码。
- middleware 顺序导致仍看到 ToolOffload 占位终态：用真实后台成功/失败集成测试验证实际事件顺序。
- 服务重启留下运行中工具卡：公开工具账本必须有恢复终结策略。
- 删除范围误触业务数据：删除 repository 使用显式白名单并以保留产物测试做硬约束。
- 一次性工具被替代 Plan 重新调用：副作用状态和工具表面策略同时阻断，不能只依赖模型提示。

## 15. ReAct 活动交互需求（暂缓设计）

事件桥接和后台工具状态契约稳定后，再单独评审活动交互。本阶段不扩展或重排当前 `ReActActivityCard`，也不把以下记录视为活动卡方案确认。

已确认的产品目标：

- 用户在当前视野内始终能看到最新的观察、简短思考和下一步行动，保留“边观察、边判断、边行动”的 ReAct 感受。
- 不展示模型原始思维链、系统提示、内部 Agent 名称、内部任务 ID、工具参数、文件路径或原始工具结果。
- 工具执行时展示准确的公开工具名和持续计时，例如“正在调用 get_current_plan_step_tool +Ns”。
- 工具与触发它的 ReAct step 必须有明确关系。
- 超过后台阈值的工具保持运行态；首轮模型回复结束不能让工具或整个活动提前显示完成。
- 后台工具的真实完成、失败或中断使用原 call ID 原地终结。
- 长工具链中，最新活动不能因为持续向上追加而离开用户当前视野。
- 请求发出至首个公开活动到达期间显示“正在思考”占位。
- 最终回答与过程活动保持信息层级区别，但不能遮断后台任务的后续进展。

后续需要用同一个真实导航任务制作并比较两个方向：

1. 底部实时活动区：在输入框上方固定展示当前 ReAct step，历史步骤折叠或进入时间线。
2. 按 ReAct step 分组追加：每一步包含观察、简短判断、动作与工具状态，并确保自动定位到最新一步。

评审维度包括信息密度、长任务可追踪性、后台任务延续、滚动行为、移动端行为，以及活动过程与最终答复的视觉关系。
