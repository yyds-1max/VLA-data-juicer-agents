# VLA多场景数据闭环处理智能体系统架构

## 一、整体模块
整个系统未来工打算实现以下几个模块：
1. 闭环仪表盘
在这里展示一些总体的系统数据信息，比如已经采集了多长时间的数据、已经标注了多少数据、模型训练信息，数据闭环处理的流程（这里最好设计成可以实时展示正在处理的数据目前所处的处理过程），正在训练的模型的指标变化曲线，最近活动提示等内容。

未来系统打算接入导航数据、机械臂数据。所以闭环仪表盘中需要可以选择分别展示导航数据、机械臂数据。模型也是分为导航类模型和机械臂类模型，最好选择时模型相关信息也根据改变。

2. Agent工作流
这部分展示的是各个场景数据的闭环处理流程。
比如导航场景的数据闭环处理流程就是： 
数据源接入->预处理管线->自动标注->质量检查->条件分支->模型训练->仿真估计->部署发布

机械臂场景的数据闭环处理流程暂时未定，需要预留接口
该部分的实现方式先以展示工作流和目前所选定的数据目前所处的流程为主，暂不已实现拖拽画布创建智能体工作流为目标。

3. 数据管理
该部分已经实现一部分，可展示导航数据、机械臂数据的原始采集数据的信息、拆解后、同步后的数据信息，还可以查看同步后的图像。机械臂数据展示暂时为占位。
未来还应该联合展示采集/同步状态、自动标注和验证生命周期。自动标注相关状态以
[自动标注总体路线](automatic-annotation-roadmap.md)为权威，主要流程为：
待处理->已拆解->已同步->处理中/待首帧标注->已标注/待轨迹复核->已验证。
同一日期或 clip 内部进度不一致时展示“部分完成”，不能仅根据文件是否存在推断审核状态。
数据表后续提供“交给 DataPilot”、进入标注工作台、进入人工复核和查看已验证
版本的入口。DataPilot 是处理任务的唯一所有者；工作台只采集人工标注/Fix 输入，
不形成独立的手动处理流水线。具体接入顺序以自动标注总体路线为准。

M3 起，数据管理页把上述两条状态轴作为同一服务端读模型联合展示：导航目录仍是
采集、拆解、同步事实源，`AnnotationStore` 是标注、后处理、复核和兼容发布事实
源。页面不得用目录存在性猜测审核状态。显式“刷新”只重新读取当前路由的事实，
保留筛选、展开项和 URL，不启动任何处理任务。

4. 自动标注
该板块从导航同步产物开始，不重复执行拆解、同步。V1 先支持 Web 首帧标注、
Tracking、既有导航后处理，以及后处理完成后的三维轨迹人工复核/Fix；不建设二维
人工复核或二维 AI。

处理链保持唯一：

```text
用户选择日期和外层 clips
→ DataPilot / MainRouter
→ NavigationDataAgent 调查并选择规范化领域决策
→ Application Service 校验
→ 冻结 Runtime 执行
→ Web 工作台采集首帧标注或人工 Fix
```

页面不得让用户选择脚本、gridmap 处理策略、轨迹变体或直接启动 Tracking/
后处理。LLM 负责理解、调查与规划，系统负责精确映射脚本、参数、路径、状态和
产物。自动标注模块保持一个侧栏入口，内部使用：

```text
/annotation/jobs                 标注工作台
/annotation/reviews              人工复核
/annotation/reviews/{review_ref} 三维 Fix 工作台
```

M2 的人工复核页只提供人工 Fix；DataPilot/模型辅助复核按钮、置信度和 AI
候选修正统一在 M4 上线。

M3 完成自动标注资产视图整合：仪表盘只展示真实的已标注总量与覆盖率，不承载
逐状态审核队列；细分生命周期、部分完成数量以及 Job/Review/历史已验证版本深链
集中在数据管理页。历史 `*_trajectory_fix_five.json` 只有经过停机、显式清单、
路径约束和 SHA-256 校验后才可登记为已验证，在线请求不得扫描目录后自动晋升。

M4 的模型辅助复核因当前收益与可行性尚未验证而延期，不是本轮自动标注闭环的
上线门禁。

自动标注的已确认边界、工程约束、状态语义和分阶段路线见
[自动标注总体路线](automatic-annotation-roadmap.md)。

5. 模型训练
人工复核审批通过的数据集可以用来训练VLA模型。这部分可设计成用户选择数据集和要训练的模型，并设置好训练参数，接下来由智能体来监控模型训练过程。训练结束后，智能体用本次训练最优的预训练权重对测试集测试，记录指标和结果。

6. 测试/仿真
这部分功能以后再设计。


## 二、智能体模块
智能体模块的设计参考goal.md文档。

智能体模块遵循明确的职责边界：LLM/多模态模型负责意图理解、规划、推理，并可基于系统提供的受控证据执行辅助审核；确定性系统负责数据搬运、格式转换、参数精确传递、状态迁移、校验和恢复。几何标注、轨迹、路径、内部 ID 和某些工具参数不得依赖 LLM 在自然语言中精确转述，部分工具参数需要借助LLM灵活的思考、推理来填写的，可由LLM/多模态模型来填写。模型辅助审核需要保留证据与 revision 绑定、结构化报告、置信度和审计记录。模型可以通过受约束的领域指令生成独立候选修正版，但不能原地修改正式业务产物、发布训练文件或代替人工最终批准。

M2 起由 DataPilot 统一拥有自动标注处理任务。NavigationDataAgent 调查
localization、gridmap、已有产物和 Runtime 能力，只选择系统公布的
`GridmapDecision` 与 trajectory variant；系统验证事实与决策一致后才执行冻结
业务 Runtime。后处理完成时原处理任务结束并释放任务槽，DataPilot 询问是否继续
Fix；用户确认后创建关联的新 Fix Task，不能复活旧任务或让 pending 复核长期占用
会话活动任务。
